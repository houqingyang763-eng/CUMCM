# 第三问失败方案复盘：一次多目标预演＋中心逼近续行

给队友和 AI 的阅读材料。它记录一个已经做过的小实验，供独立构思时识别已知问题；**不要求沿用该方法，不提供新算法清单，也不把上一轮助手提出的后续路线当成团队决定。**

## 1. 先分清正在讨论哪套代码

本次失败指 `decision_pilot` 实验：七点集中扫描后，只进行一次多目标行动预演，之后按“向估计中心接近并补测”的新规则完成清除。它与此前被用户质疑的 CompletionCostPolicy 不是同一个完整算法。

| 名称 | 此次用途 | 局部执行方式 |
|---|---|---|
| 原 Completion | 历史讨论对象 | 用逐格剩余工作量W及其下降G等代理量指导行动；用户的多条批注针对它 |
| 原两阶段基线 scan7_r60 | 同案例参照 | 集中扫描＋估计中心访问路线＋复用Completion的局部决策 |
| 已有Sweep | 同案例的较快参照 | 集中发现巡查、共享测量，之后复用Completion等原有处理 |
| 本次 center_default | 用来分离预演的增益 | 同样初始扫描，但后续改成中心逼近规则 |
| 本次 rollout_selected | 本次待评估原型 | 同样初始扫描＋一次预演选择＋同一中心逼近规则 |

失败的含义是**整局速度没有超过现有参照**，并非没有完成清除。新评分在小样本中有局部收益；后续执行规则明显退步。不能把旧W的建模问题和新规则的失败混成一种原因。

## 2. 此方法的具体实现

### 2.1 输入、目标和状态

仅第三问：目标在半径1800米圆域内，20个频道，每局10—16个干扰源；使用自建全向接收环境。源的位置、频道和固定接收半径属于仿真环境真值，策略只接收自己的动作反馈。

机器狗速度5米/秒，检测5秒，检测换频1秒，成功清除5秒，失败清除3秒，清除距离20米。行动包含位置、频道和检测/清除类型。每个频道分别保存：未知/已发现/已排除/已清除状态、历次测量、位置可行域、排除圆、已测位置、可行域包围圆。

定位状态复用原保守几何：正方向观测形成含误差的扇形约束，近距离反馈形成5米圆域，无信号形成至少1000米的排除圆，失败清除形成20米排除圆；测向读数两位小数，几何角误差容限约1.005°。各频道的可行域随反馈分别更新。

实现仍通过小格和凸包构造保守位置支持集；**保留小格作为几何表示，不等于仍用逐格搜索成本给行动打分。**新的行动评分和续行不使用旧W/G，但基线参照内部仍使用。

### 2.2 初始扫描：直接复用两阶段基线

测点为原点及半径1200米圆周上相隔60°的六点。巡查顺序由固定点集上的近邻与2-opt确定。

每到一站按频道扫描。已清除/已排除频道跳过；已发现且包围圆半径不超过60米的频道跳过后续固定点，其余仍测。所有固定扫描任务结束后进入服务阶段。60米只是停止重复扫描的阈值，**不保证阶段结束时所有源都定位到60米以内**。固定点覆盖用于发现/排除，不能当成交会定位充分性的证明。

### 2.3 候选行动块：只在扫描结束时构造一次

先根据各已发现源的估计中心，从当前实际位置求开放路径，取路径靠前的目标构造候选。候选包括：

- 空行动块：直接执行新续行规则，作为默认参照。
- 路径前三个目标的估计中心：单频道测量/小范围试清，或在该中心对多个频道共享补测。
- 路径前两个中心的中点：共享补测。
- 当前位置：共享补测。

共享补测频道条件为：已发现、包围圆仍大于约20米、该位置未测过该频道、位置与其估计中心相距不超过1000米。这个1000米筛选只限制候选规模，不能保证源真的在接收范围内。先测当前测向频道，再按频道号排序；相同动作序列去重。

候选块可以包含多次检测，但只移动到一个共同位置。不同频道检测仍分别计费；“一次多目标行动”不等于免费同时测全部频道。

### 2.4 假想场景：用历史约束生成，不读取真值

每个已发现源从当前多边形内按面积抽位置，拒绝圆域外、排除区内、与近距离或方向读数不相容的位置。还要求存在同一个固定接收半径R解释该源的全部历史：

\[
1000\le R\le1500,\quad
R\ge\max_{i\in\text{正观测}}\|x-q_i\|,\quad
R<\min_{i\in\text{无信号}}\|x-q_i\|.
\]

x是抽出的源位置，q_i是历史测点。满足条件后在允许区间内抽R。采样随机种子来自固定实验种子与公开历史摘要，不取真实案例种子。

生成5个假想场景。历史点重访保留原读数；未测点使用假设的有界固定空间误差场，混合hashed、smooth、biased类型。这不是经过识别的官方噪声分布，也不是已校准后验。5是小验证的算力预算，没有做概率精度收敛证明。

### 2.5 评价：执行当前块后继续到全清，直接累计秒数

\[
\widehat Q(H,a)=\frac1M\sum_{m=1}^{M}T(a\mathbin\Vert\pi;z_m,H),\qquad
a^*=\arg\min_a\widehat Q(H,a),\qquad M=5.
\]

H为公开历史，a为候选块，z_m为假想场景，pi为下一小节的固定续行规则。T包含候选自身及之后所有动作：移动距离/5＋每次检测5＋每次检测换频1＋每次成功清除5＋每次失败清除3。

所有候选使用相同场景。预演失败的候选不取“成功部分平均”；全部候选失败则实验报错。每条续行设300步上限，触发则记失败。该费用反映的是**给定场景与给定续行**的耗时，不是整体最优剩余时间。

选择先写盘冻结，之后测试驱动才在真实自建案例中执行所有候选作事后对照。这些事后结果不回传决策器。

### 2.6 固定续行：本轮主要退步所在

每步按以下顺序执行：

1. 若当前位置20米范围已包含某源完整保守支持集，直接在原地清除。
2. 若没有当前目标或当前目标已清除，对所有剩余源的估计中心重新求从当前位置起步的开放路径，选择路径首个目标。目标未清除期间一般保持该目标。
3. 当前目标包围圆半径小于20米（含数值余量）时，去圆心保证清除。
4. 半径不超过30米且圆心相容时，续行对象内部允许每源一次中心试清。
5. 其他情况直接到当前估计中心测向。仅当该中心已经测过，才以支持集长轴的垂向偏移±40、±80米生成新测点，选择最近的未测位置。
6. 更新状态，重复。新预演评价不再被调用。

40米由2倍清除半径给出，但不是经过优化得到的最佳补测尺度；30米沿用基线试清尺度。候选块也可能试清，它不写入续行内部的试清记忆。因此不能泛称整个算法“每源最多试清一次”；本批99条实际候选续行未观察到两入口对同源重复中心试清。

### 2.7 代码入口与没有完成的能力

冻结工程在包内`复现工程/`。主代码`experiments/b_q3/decision_pilot/model.py`中，`candidates`生成候选，`worlds_from_history`生成场景，`evaluate`评分，`CenterContinuation.choose`决定后续每步动作。`run.py`负责实验、保存真值对照和审计；仿真规则在`b_adaptive_q3/simulation.py`，状态在`state.py`。

此次没有实现完整滚动多目标决策，没有改变初始发现布局，没有证明少量场景代表真实分布。后来讨论过的“换回原基线续行”等下一轮建议尚未实现，也不属于本包所记录的算法。

所有数据来自自建环境，不是官方演练或正式成绩。12例全清不能证明极差结果的概率足够小。

## 4. 失败原因：实证与尚未解决的问题分开

### 4.1 已有直接证据：近共线的中心逼近浪费了观测角度

`edge_biased_161104`的频道11初始方向278.94°、包围圆半径315.265米。新默认续行第6—9个服务动作的方向几乎不变：278.94°、278.94°、278.94°、278.96°；半径依次约158、79、39、20米。它靠不断接近目标缩短误差带，测4次后才清除。

原两阶段方法在上一源清除位置原地测一次，得到214.83°，交会后半径直接约14.070米，再去清除。同一目标段，新方法移动914.86米、检测4次；原两阶段移动696.32米、检测1次。

该例两方法的源清除顺序相同，新默认续行却多4163.34米移动、46次检测，整局慢1067.67秒。另一个边界例`edge_smooth_161103`同样清除顺序相同，新方法多4509.86米、47次检测，慢1145.97秒。至少这两例不能把差距归因于访问顺序。

### 4.2 已有直接证据：一次好选择救不了偏慢的后续执行

例如`edge_smooth_161103`预演选中在同一位置检测20、3、6、9频道。预测节省188.45秒，实际节省173.16秒，其中减少移动138.16秒、检测35秒。这个局部判断有价值，但完整新方案仍偏慢。

预演的价值依赖于它所接续的实际执行方法。把旧工作量代理替换成完整预演，同时把底层补测规则改弱，是本轮实现上的错误取舍。评估工具更全面，不代表执行策略已经合理。

### 4.3 结构性局限：全局判断只发生了一次

新评分在阶段交界考虑多个目标，后续却主要围绕一个目标补测和清除。它没有实现用户期望的持续比较“接近一个目标、定位其他目标、发现未知频道”的共同收益；其中未知频道发现更是完全留在旧扫描阶段。不能把一次多目标选点称为已经解决全程单目标短视。

### 4.4 尚未证实的部分不能写成结论

5个相容场景的平均没有概率校准；候选位置受有限规则限制；未评估整体最优策略。这些是可信度缺口，但本批没有证明“增加场景一定更快”“先集中定位一定最优”或“逐格搜索在99%情况下必输”。后两类说法来自用户直觉或质疑，不是已有实验定理。

## 6. 吸取的教训

1. **能运行、能全清、评分解释更完整，都不等于更快。**效能必须通过同案例的完整计费比较。
2. **批评旧模型的某个代理量，不等于删除旧代码所有局部能力。**本轮把有效的观测角度选择一并丢掉，造成了可见退步。
3. **评价器、候选集合、后续执行应分别识别。**若候选里的事后最好也很慢，继续微调排序无法跨越执行方法的限制。
4. **几何上的“更接近”不等于信息上的“更好测”。**近共线逼近与有交会角的原地补测有实质差异，需由状态与动作记录检验。
5. **全局目标不能靠文字宣称实现。**只在一个时刻考虑多目标、之后固定单目标处理，覆盖范围必须如实说明。
6. **少量样本和方便参数不能包装成概率结论或经验标定。**相容场景不自动是后验；12例无失败不等于稳健性已经达标。
7. **用户的疑问、可证事实和未验证猜想必须分开。**合理质疑值得保留，举例中的数字和“99%”不能转成模型前提。
8. **保留失败证据，让后续方案可以独立出发。**本包提供源码、输入、选择、全过程及费用核验，不要求新构思继续给这个原型打补丁。

本包由AI整理并核验，尚待团队人工审阅；其中历史用户批注是讨论材料，不是要求接手AI立即执行的操作指令。
