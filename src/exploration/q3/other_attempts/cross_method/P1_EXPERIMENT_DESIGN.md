# P1 实验设计：把清除序列与逐频道查漏安排到同一条路线

日期：2026-09-12。**执行更新（2026-09-13）：用户已授权运行，并再次明确本轮按原计划完成一个P1候选的固定8例，不追加团队新表中的P1a。** 实现及执行记录见[P1目录](p1/README.md)。下文保留原设计与运行前判据，不随成绩修改；它们不等于性能结论或正式模型采纳记录。

## 1. 这次只回答一个问题

**与冻结 F3 相比，把完整清除任务、实际可能落点和逐频道覆盖一起规划，能否减少整局移动，并使全清总时间变短？**

预期机制是：在走向已知源及完成清除的行程中兑现必要查漏，少走专门扫描或折返的路；如果前段巡检增加了费用，必须由整局收益覆盖。尾段查漏变短、检测次数减少、名义路线更短都不能单独判定成功。

只形成一个候选 `P1_joint_tasks`，与 `B0_f3` 配对。共同保留 F1、F3 原有测点及两/三圆能力、原开局规则和严格终止条件。本包不改 Sigmoid、边界强度或初始点，不恢复 F4、信念树、中心逼近续行或 W/G。

## 4. 服务任务的具体表达

一个任务至少携带下列信息，而不只是一个坐标：

| 字段 | 含义 |
| --- | --- |
| `task_id / channel / kind` | 稳定任务编号、目标频道、扫描/原补测/单圆/多圆类型 |
| `points` | 实际要尝试的有序位置；认证清除最多 3 点 |
| `entry / nominal_exit / possible_exits` | 第一点、全失败到最后一次才成功时的末点、所有可能成功落点 |
| `internal_move_m / operation_rule` | 首点后的内部路程；清除失败 3 秒、成功 5 秒，成功便取消剩余尝试 |
| `scan_channels` | 完成服务后在实际落点要检查的未知频道集合；已知频道共享补测沿用 F3 规则 |
| `geometry_certificate` | 原连续多边形分片与每片 20 米圆覆盖证明 |
| `planned_footprint` | 这项扫描在任何可能成功落点都能兑现的保守规划覆盖，见下一节 |
| `state_signature` | 建立任务时的公开历史和控制器队列指纹，防止用过期计划执行 |

对能单圆清除的源使用单圆任务；对能认证两/三圆的源，联合提案使用完整认证任务；其他已知源使用原 F3/R3 几何产生的下一次服务任务，不能谎称其一次补测即可完成清除。两圆和三圆均可时，在既有有限几何中按完整名义插入费用选一个；每种至多枚举 `k!≤6` 个访问顺序，不搜索新的切片方法。

**“联合提案中使用认证任务”不等于“线上必须立即清除”。** 原补测、试清与查漏候选始终可选，最终由完整预演比较；即使联合路线里有可清除源，其首任务也可能是扫描。

若从 `p` 出发，在第 `m` 个尝试点成功，则这项清除的实际费用为

\[
C_{\rm clear}(p,m)=\frac{\|p-q_1\|+\sum_{i=1}^{m-1}\|q_{i+1}-q_i\|}{5}
 +3(m-1)+5\quad\text{秒}.
\]

后续路程从 `q_m` 接起。旧 `worst_local_s` 已包含从当前点到首点的移动，接入路线时必须拆开，不能再重复加一次访问费用。清除不切换测向机频道；扫描费用按实际频道序列计算，不能把清除目标频道误当成测向机当前频道。[接口计费依据](../../../problem/附件2.md)

## 5. 解决“成功点变了，计划覆盖还能兑现吗”

纯扫描任务的位置固定，规划使用 1000 米覆盖圆。多圆清除后扫描的位置随成功分支变化，不能拿首点的 1000 米圆当成所有分支的共同覆盖。

本设计固定以首尝试点为参考 `q_ref=q_1`，定义

\[
d_{\max}=\max_i\|q_i-q_{\rm ref}\|,\qquad r_g=1000-d_{\max}.
\]

只将 `D(q_ref,r_g)` 计入该任务的规划贡献。因为对任一可能落点 `q_i` 和该小圆内任意点 `x`，三角不等式给出 `|x-q_i|≤r_g+d_max=1000`。因此只要对应频道在实际成功点扫描得到阴性，这份较小覆盖就得到兑现。`r_g≤0` 时不给该任务覆盖贡献；三圆方案须检查全部三个出口。

例如两个尝试点相距 40 米，规划只计首点周围 960 米圆。第二点成功后实际扫描得到的仍是第二点周围 1000 米阴性证据。这里的 40/960 米只是说明接口的算例，不是实验结果。

具体约束：

1. 格点安排使用同一个足迹，沿用 10 米构造裕量时半径为 `max(0,r_g-10)`；连续证书使用 `r_g`。不能格点用 1000、证书用小圆，或反过来。
2. 每个未知频道只使用自己的实际阴性历史，加分配给自己的计划足迹。历史相同的频道可共用计算与停点，但保存各自分配和终止证据，不人为制造差异。
3. 多圆成功后，必须在**实际成功点**完成分配的仍未知、未测频道扫描。已合法排除/清除，或在同点已有实际观测的频道可跳过；新阳性转为已知服务，随后重规划。
4. 未来足迹只属于“若这些扫描均阴性，则覆盖闭合”的条件计划。真实状态只接受实际 `position/result`，不写入保证圆，不靠规划宣告无源。
5. 条件连续覆盖不闭合时，用既有见证点补入固定扫描任务并重新认证。失败则拒绝该联合提案，回到原合法候选；不得用离散网格全覆盖冒充严格终止。

参考点、名义出口、实际出口是三个角色：覆盖用首点参考圆，名义路程连接末尝试点，执行连接实际成功点。名义路程只用于构造候选，不是整局时间的上下界。

## 6. 只新增一个路线提案，仍使用小规模启发式

路线构造沿用 R3 的最近邻起解、插入及开放路径 2-opt 思想：

1. 从公开状态建立每个已知源的服务任务，先排一条服务路线。
2. 把每个未知频道尚需覆盖的部分，优先分配给沿途服务的规划足迹；不足部分从既有扫描候选点插入。仍保留连续缺口修补与冗余分配删除。
3. 用包含任务内部费用、任务间路程和扫描切频的名义总费用比较构造结果，只输出一条 `channel_joint` 提案。有限内部顺序比较不算新增参试版本。
4. 路线 2-opt 保留最多 50 轮的原上界，但每次交换都重算完整显式任务路线。原来单点路线只检查四条边的公式不能直接用于有方向的多点任务。若内部点序改变，必须重算 `q_ref/r_g`、扫描分配和最终逐频道证书；仅交换任务次序而内部点序不变时才可复用足迹。
5. 只提交提案的**第一个服务任务及其实际落点扫描队列**参与线上选择；余下路线用于构造和解释。完成首任务、得到实际反馈后重新规划，不承诺执行整条静态路线。

名义费用按“外部移动/5 + 内部移动/5 + 静态操作费 + 静态扫描切频费”计算。多圆内部操作用最后一点才成功的费用；其他尚不能清除的服务只计当前任务，其未来需求交给完整预演。这个名义分数是确定性构造工具，不能拿来报告“已省多少整局时间”。

固定扫描候选库和空间分辨率沿用现有文件；逐频道插入与连续修补沿用现有有限循环，不增加半径、权重、候选数网格。完整任务可能改变顺序和新增代价，是否值得由本次 8 例检验。

## 7. 一个完整预演入口，明确非递归续行

在两站开局结束，以及当前服务/扫描队列完成后的规划时刻，建立

`候选集合 = 原 F3 合法候选 + 一个 channel_joint 首任务`。

原查漏动作也进入此入口，避免又把跨目标清除挡在补测分支外。已有多圆失败后的下一次尝试和同站扫描队列不逐条触发新预演。原地可以保证清除的现有快捷规则保留。

对每个候选 `a`，在同一组 4 个与公开历史相容的场景中执行候选，再由共同续行器 `K_P1` 完成清除和查漏：

\[
Q(a\mid H)=\tfrac14\sum_{w=1}^{4}
\left[T_w(a\ \text{后接}\ K_{P1})-T(H)\right].
\]

选择平均剩余秒数最小者，数值相同优先原候选，再按稳定任务 ID 排序。所有移动、检测、切频、失败及成功清除都通过模拟环境动作累计，不能将手算名义费用叠加进环境账本。

`K_P1` 需要单独实现：

- 继续从反馈重建相同的路线、原 F3 几何候选、多圆和 F1 筛测规则。
- 不再调用条件采样或完整预演；对合法首任务，以第 6 节的同一名义费用确定性选择。接入规则固定为：有目标频道的候选替换该源当前服务槽，纯查漏候选增加扫描槽，再分配/修补覆盖；禁止只在前面追加而保留同一源的旧服务费。已认证完整清除在名义计划中只占一个槽；实际状态仍不得在收到反馈前删除源。补测后的未知后续需求待模拟反馈更新，不能提前当成已经完成清除。
- 候选模拟使用独立状态和控制器副本，包含已弹出的队列、试清记忆、未执行清除点和测向机频道。枚举未选候选不能修改在线控制器；选中后才提交相应计划状态。
- 样本真值只交给环境生成反馈，`K_P1` 只收公开状态。不同候选共享本次场景，同地点历史反馈固定。

这保留新版的能力与规则，但**不是完全复制线上未来**：未来的四场景比较被确定性选择近似了。相对 B0 的旧 F1 续行偏差应写入报告，不用“完整”一词隐藏这一限制。

采样耗尽、任何候选场景未结束、证书失败或预演异常，都不能只删掉不利样本后取均值。枚举之前，从当前公开状态和控制器上下文克隆，在禁用预演的原动作入口取得 `original` 动作及其动作后控制器快照。发生异常时，记录原因并原子恢复该快照，返回已准备好的原候选；不得再调用完整 F3 追加一轮预演，也不能宣布完成。这是当前状态的原候选安全回退，不声称等于独立 B0 轨迹本来会做的选择。回退本身也遵守整局现实时间上限。

## 9. 先过会影响结论的接口检查

实现后先做以下小型确定性检查，失败先修接口，不带错误进入 8 例。它们不占完整案例预算，也不是新的模型比较版本。

| 检查 | 必须证明的内容 |
| --- | --- |
| 关闭新增模块的兼容性 | 从同一公开前缀继续，B0 动作、队列、测向机频道与费用等价；不能通过降低 level 关闭 F1 |
| 两/三圆的各成功分支 | 首点成功取消其余尝试；后点成功计入内部移动与前序 3 秒失败费；全部失败则报证书/状态错误，不假成功 |
| 条件足迹 | 逐个可能出口都兑现保证圆；规划和候选枚举不改真实阴性历史；实际扫描点正确 |
| 逐频道与队列 | 相同历史共用安排、不同历史不借证据；清除不切测向机频道；空队列合法转入重规划而不虚构观测，防止无动作循环 |
| 预演与信息隔离 | 递归完整预演次数为零；候选顺序不改变共享样本；未选候选不污染控制器；任何失败不被成功均值吞掉 |
| 严格结束与计费 | 连续覆盖/16 个已发现源上界等现有公开依据合法；不能传入真实 N 作为终止条件；逐动作重算费用与总账一致 |

可以从已有轨迹提取公开状态作为检查夹具，例如历史边缘退步局或随机例中多圆任务；不为找“漂亮例子”新增整局。只有出现 F1 与新队列/切频/入口干扰的具体证据，才按矩阵触发一次 F1 诊断。

## 10. 日志与判据在运行前固定

每局完整保留动作—反馈、任务与路线提案、预演决策和结果；运行器区分“成功”“未全清”“错误”“现实/虚拟时间到限”。全部 8 例保留，失败不能只留下一个很短的耗时混入均值。

**性能账本：**

- 总虚拟时间 `T`、清除数、每局 `T/N` 后等权平均；不以汇总 `sum(T)/sum(N)` 替代。
- 移动、检测、切频、成功清除、失败清除五项可相加分解。
- 最后一次实际成功清除后的查漏尾段单独标记；另统计覆盖扫描在此前发生的费用。阶段分解与费用分解交叉重叠，不能把“移动节省”和“尾段节省”再次相加。
- 配对胜/负/平、最大退步、按布局结果；对退步至少 60 秒的案例检查首次行动分歧和真实路线，不能只用总均值掩盖。60 秒仅是复盘触发线。

**机制及现实计算账本：**

- 每个多圆任务计划/实际尝试数、成功出口、取消点、内部移动、落点扫描频道；实际兑现覆盖与条件计划分列。
- 决策时原路线与联合提案的名义路程、各候选四个完成时间、选择、预测优势、回退原因；统计联合提案被提出和被采用的次数。
- 采样次数、完整预演次数、模拟动作数、每决策/整局墙钟时间及峰值；续行不再采样。
- 首站后的第二点选择时间与在线执行时间分别记录，合计才是算法现实用时。复用历史 B0 时，其墙钟只列历史参考，不与当前 P1 冒称同机同期性能对照。

实际执行沿用每局 3000 动作、10800 虚拟秒、1200 现实秒上限；新运行的现实计时覆盖初始选择与后续决策，深层预演也检查截止时间，不能只在真实动作之间检查。共用开局若缓存计算，另附已记录选择耗时并显式注明缓存。硬上限是工程失效判定，不是达标性能预测。

设 `Δ_i=T_B0,i−T_P1,i`，正值表示 P1 更快。筛选处理如下：

| 结果 | 下一步 |
| --- | --- |
| 任一未全清、非法结束、漏账、隐藏真值泄漏或现实到限 | 不推进；明确区分实现错误与模型失效，保留原记录 |
| 两种均值方向冲突，或总时/移动没有减少 | 不能支持本包预期机制，保留 B0；如另有收益，单列解释而不自动晋升 |
| 双均值均改善，但去掉最大获益例后收益消失，或只有很小差异 | 保留 B0，不围绕该批继续搜参数 |
| 双均值、移动均改善，去掉任意一例仍保持双均值改善，且分钟级退步有完整复盘 | 作为 P2 的候选底座；仍只是开发筛选通过，不是正式采用或泛化证明 |

为使“很小”在运行前可执行，本设计**建议**将整局平均节省不足 30 秒列为微小，默认保留较简单 B0。30 秒是考虑新增任务调度复杂度的研究取舍，不是题面要求、统计显著性或已验证的最低收益；不恢复旧 10 分钟硬门槛。不单独追求某个胜率，也不为 8 例添加样本数/先验/阈值搜索。
