# 后续动作模型与实现对应

## 不变的条件

第三问全向静止源、每频道最多一源、总数10—16、接收半径1000—1500米。策略只接收公开状态。测向5秒，切频1秒，失败清除3秒，成功清除5秒，速度5米/秒；清除不切换测向频道。原地反馈固定。结束仍依赖保守几何覆盖与清除结果。

初始第一站和第二站的选择机制保持原版。配对运行器由同一个第一站公开历史算出第二站并冻结给所有版本；这些第二站不会因后续优化版本改变。

## F1：可证明冗余的阴性测量过滤

`refined.py:dominated_negative`。对于已发现源的保守凸区域S，旧阴性测点p和新测点q，若所有x∈S满足

`|x-q|²−|x-p|² ≥ 1e-4 平方米`，

则旧阴性反馈已经蕴含新阴性反馈。差值对x为仿射函数，所以检查全部凸多边形顶点足够。只在共享扫描队列中删除此类频道。不规定最小测点间距，不把半径不变当成没有信息。

兼容旧调度器的限制：如果一个服务扫描队列全部被证明冗余，暂时保留首个合法检测以避免原调度器空队列报错，记入`kept_to_progress`；`current_view`直发动作也不经过此过滤。没有伪造零成本观测改变公开状态。这两项是仍可继续审查的冗余来源。

## F2：保留多个测点，并比较扫描未知频道

`RefinedPolicy.choose_joint`在新服务停留决策中保留原动作。在本来要横向补测时，同时保留长轴法向两侧的候选点，不先按移动距离丢掉一侧；对未知频道原来不扫描的站点，同时考虑加扫未知频道。清除后自然停留时也可比较是否补扫未知频道。

两侧偏移仍沿用原几何生成器：`min(300,max(30,包围半径/2))`米。本轮更改的是候选保留和选择机制，并未声称连续空间全局最优，也没有添加靠边界惩罚。

每个候选先在同一批条件场景中执行，再用固定F1规则运行到全清。候选评价为

`Q(a|H) = 条件场景中[执行候选a后按F1完成全部任务所需秒数]的均值`。

移动、全部扫描、切频、失败清除、成功清除及最终查漏都由模拟动作直接计入。不是发现量、精度和距离加权拼接的分数。所有候选使用同一后续控制器；不递归调用新选择器。

这是有限候选的一步条件试算，不是求解完整POMDP，不保证全局最优。后续F1本身是启发式，且条件场景数有限，预测排序可能与实际不符。新增选择以`at_action`记录观测前缀、候选费用、选择及回退原因。

## 条件场景的概率假设

`posterior.py`。假设位置在任务圆内均匀，N在10—16均匀，给定N的频道子集均匀，接收半径在1000—1500均匀；历史方向误差用有界均匀似然近似。不是官方随机生成规律。

对每个可能位置x，用全部公开历史计算允许的半径区间 `[L(x),U(x)]`：有信号记录给下界，阴性记录给上界；还检查方向、near和失败清除排除条件。空间提议按区间长度`max(0,U-L)/500`加权。已知源在保守凸多边形内均匀提议；未知源在保守未覆盖叶格的并集中按面积提议。每频道256个提议点，用离散重要性重采样近似条件分布。

未知频道j的活动似然质量记为z_j。K是已见过的源数（含已清除）。未知活动子集A的后验权重为

`P(A|H) ∝ [∏(j∈A) z_j] / C(20,K+|A|)`，且`10≤K+|A|≤16`。

利用基本对称多项式的动态规划先抽剩余源数、再抽频道子集。已清除源不进入后续模拟世界，但计入K。任何有限池耗尽、场景试算失败均回退原动作，绝不宣布目标不存在。未来噪声为固定空间哈希场，同地点已知历史反馈原样保留。

开发和首次确认使用4个条件场景。这个数值是计算配置，不是收敛保证；最终报告须说明其排序误差风险和场景先验失配。

## F3：少量清除圆作为候选动作

`clearing_plans`沿定位多边形长轴分别作两等分、三等分，对每片求包围圆并独立复算全部顶点距离。只有每片都被20米圆覆盖时才形成清除候选，因此联合覆盖原区域，最多执行对应次数即可保证清除。

访问顺序枚举至多6种排列，取总路程最短的顺序。尝试失败后继续下一个清除点，成功则立即停止该序列；成功后保留自然停留扫描机会。此处顺序按路程确定，尚未优化先成功的概率顺序。

选择器把完整清除小路线和原测量动作放在相同条件场景中比较。不是简单放宽30米阈值。两圆/三圆仅是当前可构造的可行解：构造失败不证明不存在更好的覆盖布局。

## F4：随机轨迹审查后的独立样本复查

`verified.py:VerifiedPolicy.select_candidate`。第一批4场景若选中替代动作，再抽独立8场景，只比较该赢家与原动作；第二批平均剩余时间仍较少才替换。第一批保持种子盐310912，第二批使用310913。所有其他先验、几何、候选生成和F1续行不变。

该微调只试图减小第一批赢家偏差，不是统计显著性检验。它仍可能误拒好动作，不能修复先验失配，也不能纠正第一批未选中的好候选。新样本池为空或模拟失败仍回退原动作。F3新增选择钩子前后在随机案例的总时与动作完全一致，默认行为未变。

## 实验与复现

- `test_refined.py`检查几何证明、连续覆盖、条件采样、源数后验动态规划、历史固定及新站候选确实参与比较。
- `run.py`运行配对批次，保留每个版本的动作、独立账本、元数据和失败。
- `analyze.py`依据真值坐标和官方计时公式逐条独立复算实际轨迹，输出配对CSV、按布局结果、退步案例和分层bootstrap区间。
- `audit_trace.py`逐步标记实际信息变化、剩余冗余和漏扫机会。它使用真值的部分仅为事后诊断；可选候选反事实均接相同F1后续，不能当作新策略实际整局表现。

典型命令从仓库根目录执行：

```powershell
py -3.13 experiments/b_q3/refinement/test_refined.py
py -3.13 experiments/b_q3/refinement/run.py --stage confirm --out experiments/b_q3/refinement/runs/reproduce_confirm --workers 3 --modes current f1 f2 f3 baseline
py -3.13 experiments/b_q3/refinement/analyze.py experiments/b_q3/refinement/runs/reproduce_confirm
```

微调复验：

```powershell
py -3.13 experiments/b_q3/refinement/postcheck.py --stage micro --out experiments/b_q3/refinement/runs/reproduce_micro --workers 4 --modes current f1 f2 f3 f4 baseline
py -3.13 experiments/b_q3/refinement/analyze.py experiments/b_q3/refinement/runs/reproduce_micro
```

`postcheck.py`是续跑运行器，存在结果时复用已完成轨迹，另写每次运行的源码散列。复现应使用新目录；复现指定随机场景时先把已有`cases.json`及`selection.json`复制到新的案例目录，不再调用随机抽样。绘图脚本读取既有日志，不触发策略或随机抽样。

`run.py`的已有输出目录受源码散列检查保护；`postcheck.py`支持继续填充新版本，保留每次运行清单。复现改动后的代码应使用新的输出目录，不覆盖旧轨迹。未启动官方测试，全部结论限于相应自建案例与假设。
