# 多目标剩余路线：可运行候选与保留反例

日期：2026-09-11。**当前不替代 CompletionCost 默认策略。** 新增 `RouteCostPolicy` 已完整实现并在四类开发案例中全清，但两局略快、两局更慢，均值退化 3.91%。完整中心路线并未自动转化为更短的真实运动路径。

## 实际接口

```python
from route_cost import RouteCostPolicy, RouteCostConfig
policy = RouteCostPolicy(RouteCostConfig())
action = policy.choose(state)
```

`RouteCostPolicy` 真实继承冻结的 `CompletionCostPolicy`；配置继承 `CompletionCostConfig`，保留 choose/config/fallback_started 等接口。没有改动 `task_cost.py`、`q4.py` 或统一 runner。发现、当前位置廉价共享检测、单个已发现目标与已有有限完成保护均沿用 CompletionCost。仅当多个目标已经发现、原策略将要移动时，才启用路线比较。

## 模型

设动作 a 在 q 执行后仍需处理的已发现目标中心为 C(a)，剩余局部清除工作代理为 W_j(a)。直接最小化

\[
J(a)=T_{\rm move}(x,q)+T_{\rm operation}(a)+\frac{L_{\rm open}(q,C(a))}{5}+\sum_jW_j(a).
\]

这里每个目标中心各作一次首站，用最近邻顺序连接其他所有中心，形成真正访问完整中心集合的开放路线；在这些路线中选从 q 出发总长度最短的一条。没有要求回到起点，也没有把它称为 TSP 最优。

W 沿用 CompletionCost 的剩余清除格/包围圆工作估计。测向动作通过同一兼容代表位置与角度误差情形估计 W 的下降，最低仍保留 5 秒成功清除；测向后中心暂用当前区域中心近似。不同目标的剩余工作全部相加，不只奖励当前处理目标的局部收益。

清除分两种情况：

- 若所有保守支持顶点都在 q 的 20 米范围内，才在预测中删除该目标及其剩余工作，当前操作计 5 秒。
- 否则按**失败分支**评分：操作计 3 秒，复制该目标的公开状态，加入 q 的 20 米排除圆后重新计算支持、中心和剩余清除工作；仍保留该目标及未来成功操作。不把试清假定为必然成功，不将这个预测副本写回真实状态。

候选包括 Completion 的原动作、各目标可清中心或最近剩余格中心，以及原有观测候选中的近处点和每目标两个较有信息价值的点。默认保留最近 36 点，加入全部目标中心，保证不会因截断而完全漏掉某个已发现目标。

## 估计适用范围

L 是可行的**中心访问路线**长度；W 仍为启发式工作代理，所以 J 不是整个清除程序的可行完成时间上界。它也没有预测尚未发现的源、未来目标中心移动、多频道同点观测的额外收益或所有后续方向反馈。只在多目标移动处调用，是为了继续沿用已有稳定的发现与进展机制。

如果用当前中心代理不确定区域会误判路径，计算更长的路线本身不能消除这种误差。当前结果支持保留它作为独立方向，后续需判断区域不确定性/未来发现是否值得更强建模，不围绕四例继续调参数。
