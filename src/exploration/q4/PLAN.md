3. 25点保证发现，不保证每个源已精确定位。按当前保守位置区域的估计中心规划开放访问路线，使用已有中心路径DP；清除一个目标后从实际位置重排余下目标。

## 2. 评价口径

- 首先统计每局实际全清与清除比例；漏清、报错、超时案例全部保留，不能通过少清目标取得低耗时。
- 主效率指标为每局 `T_virtual / N_cleared`，单位秒/源；仅在相同案例全清前提下解释速度优劣。整批另报全清局数、逐局每源时间均值，不混同总时间之和除以总源数。
- 同场景配对比较整局总时间和节省比例，报告平均、最差局、退步案例、程序实际运行时间。
- 分拆移动、测向、切频、失败清除和成功清除费用；专门查漏与失联恢复作为动作标签解释成本，避免重复计费。
- 开发案例和最终确认案例分开；开发覆盖不同位置布局、混合比例、发射方向、接收半径与固定空间误差。压力重点为边界向外、切向、接收半径1000米、接近共线和源数两端。
- 开发阶段可以反复诊断。最终确认前冻结代码，再运行新种子；若确认失败促成改动，应将原批次转为开发证据，并另取新确认案例。
- 性能目标不凭空指定某分钟数。先测 B0 与较强旧方案的实际水平；只有可重复的整局收益且全清未受损，才保留新模型。有限自建结果不外推为官方隐藏案例保证。

## 4. 第一版结果差时的处理

1. **漏清或异常：**先区分状态误排、错误结束、方向边界、数值退化、局部不终止或运行预算问题。构造最小反例核对；修正确性前不做速度排名。
2. **全清但慢：**取退步局完整动作链，与同案例 B0/旧方法比较成本。确定是发现太晚、失联绕路、无效检测、失败清除移动，还是内部计算过重。
3. **定位机制问题：**在冻结公开历史上比较有限候选，检查预测的后续节省是否发生。真值只供事后诊断，不交给在线决策；固定续行反事实不直接冒充整局因果归因。
4. **决定修复或换路：**若是实现错误或明确局部缺陷，修复后重查；若理论假设与题目不匹配、候选遗漏重要动作，或节省局部检测却反复增加整局移动，修改表示/动作设计或更换思想。不能默认增加样本、搜索深度或经验权重就会有效。
5. **及时淘汰：**对无稳定净收益的机制停止叠加。用新开发案例检查改动是否重复有效；保留可靠 B0/旧方案作为交付退路，明确新思想未获支持的证据，不能包装成成功。
